## API mock (`agenda-libre-api`)

- Backend Hono + Zod + DB in-memory en `:8787` (seed barbería / podología / cliente).
- Auth mock: `Bearer mock:<role>:<userId>` o `X-Mock-User` + login seed.
- Middleware: `request-id`, logger, rate-limit (180/60s → 429), `Content-Type` JSON.
- **slow_request**: logger warn si `durationMs` > 200; `GET /health` expone `slowThresholdMs`.
- **X-API-Version** `1.0.0` en todas las respuestas + `version` en `GET /health` (CORS Expo web `:8081` + `Idempotency-Key`).
- Cache TTL pa’ GETs idempotentes; mutaciones invalidan.
- OpenAPI: `GET /openapi.json` + `npm run openapi` (copia a `docs/`).
- Dominios: services, clients, appointments, availability, policies, waitlist, storefront/vitrina pública, cash, reminders, honorarios (retención 15,25 %), team, notifications, reviews, gallery.
- **Idempotency-Key** opcional en `POST /appointments` y `POST /clients` — mapa in-memory 24h; mismo body → replay; body distinto → 409.
- Smoke: `npm run test:smoke` (health, openapi, login, services, honorarios, vitrina, idempotency).

## Front · wiring API

- Cliente fetch (`api/client.ts`) + endpoints por dominio; token Bearer auto.
- Cache GET en cliente + invalidación post-mutación.
- Dual-write `store/apiActions.ts`: con `EXPO_PUBLIC_USE_MOCK_API=true` pega al mock y espeja Zustand; si cae la API → soft-fallback local.
- `hydrateFromApi()` al boot; sesión en AsyncStorage.
- `appointmentsApi.create` manda **uuid** en `Idempotency-Key` (o el que le pases).
